Confidential records. Better questions.

The filing stays protected.
The City gets an answer.

What if a housing agency could ask a confidential income-and-expense filing a question without receiving the filing? Housingproof explores that workflow using synthetic New York City RPIE records.

0.1.0-alpha.1 / synthetic prototype

The foundation is here. Real proofs come next.

The repository includes a source-mapped dataset, validation, signed simulator receipts, a local interface, tests, and a build plan. Genuine ZK proof generation and independent verification are not implemented yet. The local app withholds unverified answers.

This page presents the project. It does not run a custodian service or prove statements. All records and issuance are simulated.

A small trial, inside DOF.

Audit the open-source code. Run it in a DOF-controlled environment. Start with synthetic records, then evaluate about 100 authorized sample filings after review. The proposed workflow validates the import, lets a reviewer choose an approved question, and returns an independently checkable answer once genuine proof generation is implemented.

DOF keeps the records.

Source filings, normalized inputs, private salts, and signing keys stay inside the custodian environment.

The recipient checks an answer.

An authorized recipient would receive only the approved answer, permitted public metadata, and proof. No source filing is needed to verify it.

The trial tests the boundary.

Compare against DOF's internal calculation, reject altered proofs, and check that source data never reaches the recipient.

Proposed pilot: bulk import, separated roles, and real proofs still need implementation. A proof verifies computation on reported values; it does not establish the truth of a filing or permission to disclose an answer.
